## 二、功能变更说明

### 2.1 新增功能

**日志格式化增强**：
- `log_vprintf()` 新增 `%0Nx` 零填充十六进制支持（如 `%04x`、`%02x`、`%08x`）
- `log_vprintf()` 新增 `%zu` 类型修饰符支持（`size_t`）
- 新增宽度解析器（`width`）、零填充标志（`zero_pad`）、长度修饰符（`%z`、`%l`、`%ll`）

### 2.2 修改功能

| 模块 | 变更 | 影响 |
|------|------|------|
| `kernel/pagetable.c` | `page_table_init()` 直接通过内联汇编读取 CR3 | 消除编译器优化可能导致 `kernel_cr3` 为 0 的问题 |
| `kernel/pagetable.c` | `read_cr3()` 改为 `static inline` | 确保函数始终内联，避免外部链接问题 |
| `kernel/pagetable.h` | 移除 `read_cr3()` 公开声明 | 函数仅在 `pagetable.c` 内部使用 |
| `kernel/net/dhcp.c` | `dhcp_init()` 不再自动调用 `dhcp_run()` | 消除双重 DHCP DISCOVER 发送 |

### 2.3 兼容性变更

- **无 API 破坏性变更**。所有修改均为内部实现细节调整。
- `read_cr3()` 从公开 API 改为内部函数，但该函数未被任何外部模块使用。
- 系统调用接口无变化。

## 三、架构调整文档

### 3.1 CR3 读取路径优化

**问题**：`get_kernel_cr3()` 在 selftest 中返回 0，导致 `[FAIL] get_kernel_cr3 returned 0`。

**根因分析**：
- `page_table_init()` 通过 `read_cr3()` 函数间接读取 CR3 并存储到 `kernel_cr3`
- `read_cr3()` 声明为 `inline`（非 `static`），编译器可能不内联，生成外部调用
- 在 `-O2` 优化级别下，编译器可能将 `kernel_cr3 = read_cr3()` 的存储操作优化掉

**解决方案**：在 `page_table_init()` 中直接使用内联汇编读取 CR3：

```c
/* Before (v4.1.6) */
void page_table_init(void) {
    kernel_cr3 = read_cr3();  // 间接调用，可能被优化
    ...
}

/* After (v4.1.7) */
void page_table_init(void) {
    asm volatile ("mov %%cr3, %0" : "=r"(kernel_cr3));  // 直接读取
    ...
}
```

### 3.2 DHCP 初始化流程优化

**问题**：`dhcp_init()` 内部自动调用 `dhcp_run()`，而 `net_init()` 也显式调用 `dhcp_run()`，导致双重 DISCOVER 发送。

**调用链分析**：
```
修复前:
  net_init()
    ├── dhcp_init()
    │     └── dhcp_run()  ← 第1次 DISCOVER
    └── dhcp_run()        ← 第2次 DISCOVER

修复后:
  net_init()
    ├── dhcp_init()       ← 仅初始化状态
    └── dhcp_run()        ← 唯一的 DISCOVER
```

### 3.3 日志格式化架构

**增强前**（v4.1.6）：
```
%x 处理器: 仅支持 %x、%p，无宽度/填充解析
%u 处理器: 无 %z 修饰符
```

**增强后**（v4.1.7）：
```
格式解析流程: % → [flags] → [width] → [modifiers] → specifier
  flags:     '0' = 零填充
  width:     十进制数字（如 04、02、08）
  modifiers: z (size_t), l (long), ll (long long)
  specifier: s, c, d, u, x, p
```
