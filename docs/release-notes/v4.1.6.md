## 一、版本概述

v4.1.6 是一次全面的编译/链接/运行时问题修复版本，共修复 **26 项问题**，涵盖：

| 类别 | 数量 | 说明 |
|------|------|------|
| 编译错误 | 18 | 缺失头文件、类型错误、x86_64 汇编兼容性、前向声明等 |
| 链接错误 | 4 | 未定义符号实现 |
| 运行时崩溃 | 3 | 栈溢出、CPU 特性检测、内存初始化 |
| 架构修复 | 1 | 头文件循环依赖 |
| **合计** | **26** | |

编译验证环境：WSL Ubuntu 24.04 + x86_64-elf-gcc 14.2.0，**编译通过，无错误**。

## 二、功能变更说明

### 2.1 新增功能

无新增功能。本版本为纯修复版本。

### 2.2 修改功能

| 模块 | 变更 | 影响 |
|------|------|------|
| `kernel/smp.h` | `current_cpu_id()` 从 `sched.c` 的 `static inline` 提升为 `smp.h` 公开 `static inline` | 所有包含 `smp.h` 的文件均可使用，消除 `pit_handler.c` 隐式声明警告 |
| `kernel/ramfs.c` | 内部函数 `ramfs_create()` 重命名为 `ramfs_create_file()` | 避免与 `fs.h` 声明的 `ramfs_create(void)` 冲突 |
| `kernel/syscall.c` | `sys_ntohs()` 定义前移至 `sys_bind()` 之前，消除重复定义 | 解决隐式声明和类型冲突 |

### 2.3 兼容性变更

- **无 API 破坏性变更**。所有修改均为内部实现细节调整。
- 二进制接口（ABI）保持兼容，`spinlock_t` 结构定义未变。
- 系统调用接口无变化，系统调用数量保持 77 个。

## 三、架构调整文档

### 3.1 头文件依赖关系优化

**问题**：`mem.c → smp.h → sched.h → mem.h` 形成循环依赖。

**解决方案**：在 `mem.c` 中本地定义 `spinlock_t` 及锁函数，移除对 `smp.h` 的依赖。定义与 `smp.h` 保持严格一致，添加注释标注同步要求。

```
修复前:
  mem.c ──include──▶ smp.h ──include──▶ sched.h ──include──▶ mem.h  ← 循环！

修复后:
  mem.c (本地 spinlock_t 定义)     smp.h ──include──▶ sched.h ──include──▶ mem.h
       ↑ 独立，无循环依赖                                                       ↑
```

### 3.2 spinlock_t 定义统一管理

引入 `SPINLOCK_T_DEFINED` 宏保护，确保 `spinlock_t` 在多个头文件中不重复定义：

- `kernel/sched.h`: 主定义位置（带 `#ifndef SPINLOCK_T_DEFINED` 保护）
- `kernel/smp.h`: 次定义位置（带同样保护，用于不包含 `sched.h` 的场景）
- `kernel/mem.c`: 本地定义（用于避免循环依赖的特殊场景）

### 3.3 current_cpu_id() 架构优化

**修复前**：`sched.c` 中 `static inline` 函数，通过 `mov %%gs:0, %0` 读取 GS:0 为 `int`，误将 `cpu_data*` 指针的低 32 位当作 `cpu_id`。

**修复后**：`smp.h` 中公开 `static inline`，正确使用 `this_cpu()->cpu_id` 解引用 GS 段指针，语义正确且对所有内核文件可见。

## 六、用户操作手册

### 6.1 构建指南

**前置条件**：
- x86_64-elf 交叉编译工具链（gcc, ld, objcopy）
- GNU Make
- GRUB2 (用于创建 ISO 镜像)

**构建步骤**：
```bash
# 克隆仓库
git clone https://github.com/zhan1206/aurora-os.git
cd aurora-os

# 切换到 v4.1.6
git checkout v4.1.6

# 编译（Release 模式）
make

# 创建 ISO 镜像
make iso

# 在 QEMU 中运行
make run
```

### 6.2 快速验证

```bash
# 编译并运行自测试
make test

# 或在 QEMU 中手动运行
qemu-system-x86_64 -m 256M -cdrom os.iso -nographic -no-reboot
```

### 6.3 已知问题

- QEMU 默认不支持 SMEP/SMAP，内核启动时将显示 `[WARN] pagetable: SMEP/SMAP not supported by CPU, skipping`
- 部分编译警告（如 `unused-parameter`）为已知遗留问题，不影响功能
